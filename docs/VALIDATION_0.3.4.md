# 0.3.4 多媒体资料验收

## 已完成的本机检查

- 工作区 TypeScript 类型检查通过。
- Web 单元测试 24 项通过。
- 手机浏览器原有流程 14 项通过（Windows WebKit 与 Chromium 各 7 项）。覆盖授权、拒绝、取消、文字回归、附件整批导入、持久保存、类型筛选、分类、原文件字节一致导出、二进制双向同步和无网络时的本机读取。
- 新增大视频流程 2 项通过（两个引擎各 1 项）：使用真实落盘的 60 MB + 17 字节 MP4 测试文件，验证分块持久保存、刷新后保留、上传第二块时中断及重启续传、分块下载、无网络时原文件导出及全部字节一致。发现并修复开发模式组件重挂载导致重复下载的问题。
- Chromium 实际解码 PNG、PCM WAV、H.264 MP4，并验证播放时间前进。
- Windows WebKit 实际解码图片，验证音视频无法解码时的清楚提示与原文件导出。同一合成 WAV/MP4 在独立播放器中也报媒体不支持，因此不把这项结果写成 iPhone 真机播放通过。[Playwright 官方关于平台编解码差异的说明](https://playwright.dev/docs/browsers#webkit)。
- Windows WebKit 的模拟离线模式会破坏纯内存 Blob 的读取；附件离线测试改为阻断全部 HTTP(S) 请求，保留本机二进制访问。文字离线测试仍使用浏览器离线模式。
- 已用两个引擎建立旧版 IndexedDB v1，再升级到 v2，确认旧笔记正文、待同步状态、分类和标签保留。
- 生产 Web 构建、版本一致性、源代码内容检查通过。

测试图片、音频和视频由 FFmpeg 生成，位于 `scripts/browser-tests/fixtures`；没有个人资料。

## 真机反馈

用户确认该 MP4 大于 50 MB，因此原限制拦截了导入。音视频上限现调整为 1 GB，并增加分块保存/传输和进度；0 字节与超限分别说明原因，去除多余的 Error 前缀。用户这段原始视频尚需在 iPhone 上重新导入确认，不将其标记为已通过真机验收。

## 安装包验收

安装包仍需完成 GitHub 原生测试、下载校验、安装与实际 HTTP/文件读写验收后才能公开发布。这里的结果会在验收完成后补充。

## 当前能力边界

图片单个 50 MB、音视频单个 1 GB，每批最多 50 个、合计 2 GB；以 4 MB 分块处理，支持列表见 `MOBILE_SYNC.md`。电脑附件按需下载。1 GB 为配置上限，当前自动大文件验收样本约 60 MB，实际可用大小还取决于设备剩余存储和浏览器资源。完整附件原文件通过单独导出或电脑同步留存，JSON 备份只包含资料目录与文字/分类。图片识别、音视频转写、跨网络同步、后台关闭页面同步和原生 iOS 安装尚未接入。
