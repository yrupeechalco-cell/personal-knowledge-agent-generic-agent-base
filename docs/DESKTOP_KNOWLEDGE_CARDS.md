# 电脑端知识卡片试用（0.3.5）

这一轮先把电脑端的原件、位置和知识卡片分开，供真实资料试用。账户、手机卡片同步、跨设备关系推荐还没有接入；「可共享」不表示已上传。

## 怎么用

1. 从左侧打开「文件知识库」，添加一个自己选择的资料文件夹。
2. 默认进入「知识卡片」。每份已收录资料生成稳定卡片编号；原件仍在原文件夹。
3. 选择卡片，编辑摘要、多个分类和关键词，点击「保存卡片」。例如同一份报价单可属于 `项目/装修`、`主题/预算`、`人物/供应商`。
4. 用「所有分类视角」切换这些分类，或组合关键词查找。结果始终指向同一张卡片。
5. 默认所有卡片都「仅本机」。选择「可共享」并保存后，用「预览可共享内容」核对实际 JSON，再按需导出。名称、摘要和要点本身也是个人资料，应检查后选择。
6. 需要查看正文或生成 AI 建议时切换到「原文与 AI 整理」。原有模型配置与操作方式沿用；是否将正文提交给在线模型与卡片共享范围是两项独立设置。

## 本轮的数据边界

- 本机索引包含原文索引、位置、引用和知识卡片。卡片标注更新只保存索引，不修改原件。
- 导出 / 卡片快照采用 `knowledge-cards/v1` 字段白名单，只包含可共享卡片的编号、版本、显示文件名、类型、摘要、分类、标签、要点内容、来源设备、最后观测版本/时间/状态。
- 正文、引用原文字段、附件字节、完整文件路径、授权凭据不在导出结构中。用户主动填写在摘要或要点里的内容仍属于卡片内容，会随选择共享的卡片导出。
- 原件不在线或扫描后未找到时，卡片保留并提示「原件暂不可用」，可继续编辑标注。不把它当作最新原文。
- 源文件变化时保留人工分类并标记旧知识待核对。确定的同目录文本重命名可保留编号；跨目录移动、同内容多个候选、二进制文件移动的重新定位还未完善，无法确认时不自动合并。
- 「可共享」目前只用于本地快照预览与导出。没有账户上传、远端删除传播或同步冲突合并。旧手机正文 / 附件传递路由统一拒绝，避免继续自动传原件；手机上已经保存的数据不受删除操作影响。

## 如何检验

建议先新建一个测试目录，放入两三份无敏感信息的文本资料：

| 检验 | 操作与期望 |
| --- | --- |
| 多维查看 | 同一张卡片填两个分类；切换分类都能找到它，磁盘上没有额外副本 |
| 原件不变 | 保存卡片前后比较源文件内容、路径和修改时间，都相同 |
| 共享范围 | 全部默认仅本机时预览得到空卡片列表；只选一张可共享，预览和导出只包含这一张 |
| 字段边界 | 在原文放一个独特测试词，不把它写入摘要/要点；导出不包含该测试词、引用原文、电脑绝对路径或配对令牌 |
| 离线标注 | 把测试目录临时改名使来源不可用，扫描后仍能改卡片；恢复目录后再扫描，人工标注保留 |
| 编辑冲突 | 打开两份 App，先后编辑同一卡片；第二份旧版本保存被拒绝并保留草稿 |
| 重启保存 | 关闭并重开 App，卡片编号、标注与共享范围不变 |
| 原件变化 | 外部修改一份已整理资料再扫描，原来的分类保留，旧知识显示待核对 |

## 回滚位置

- 源码基线：[rollback/desktop-before-knowledge-cards-2026-09-27](https://github.com/yrupeechalco-cell/personal-knowledge-agent-generic-agent-base/tree/rollback/desktop-before-knowledge-cards-2026-09-27)，指向 `e8701c9`。
- 开发分支：`codex/desktop-knowledge-cards`，不在 `codex/mobile-app` 上直接改动。
- 上一个正式安装包：[app-v0.3.4](https://github.com/yrupeechalco-cell/personal-knowledge-agent-generic-agent-base/releases/tag/app-v0.3.4)。
- 本机数据目录：`%LOCALAPPDATA%/com.personal-knowledge-agent.desktop/document-library/`。

首次迁移读取旧 `index-v1.json` 并创建新 `index-v3.json`，旧文件不覆盖。迁移失败会报错并停止，不创建空库冒充成功。正常运行 0.3.5 只使用 v3 索引。

需要回滚时，先关闭 App 并备份整个数据目录，再运行 0.3.4 安装包；旧版会读取升级前保留的 v1 文件。v3 文件保留，因此新增加的卡片标注仍可在返回 0.3.5 后使用，但不会自动出现在 0.3.4。卡片 JSON 导出不是完整数据备份；备份应保留整个索引目录。

回滚期间不要交替在两个版本中编辑，否则两个索引会分叉。旧版可能恢复此前的原文件同步设置，按需要关闭其自动同步。原件自身的明确编辑不能通过源码标签回滚，应使用原文备份或文件历史恢复。

## 实现说明

本轮是在现有项目内独立实现，没有复制 Spacedrive 代码或素材。其研究来源见 [Spacedrive 源码研究](SPACEDRIVE_RESEARCH.md)。电脑本机位置仍使用旧文件索引；新增稳定 `resourceId` 将位置与卡片关联，卡片有独立的版本和共享范围。对旧资料编辑器保留同事务更新的本机投影，以兼容现有分类与 AI 整理。

完成账户互通前，仍需增加标注操作日志、删除记录、设备授权及冲突合并；本轮的全量卡片快照不能当作已完成的同步服务。
