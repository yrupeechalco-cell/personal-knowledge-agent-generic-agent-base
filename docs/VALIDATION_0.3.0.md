## 正式安装 App 实测

使用独立验收目录中的三份合成 TXT 和一份合成 DOCX；未将私人资料用于 AI 测试。

1. 新版侧栏显示「文件知识库」，可进入分类与 tip 页面；旧版 7 份测试资料及已保存摘要、分类成功迁移，两个旧监测目录的暂停设置保持。
2. 通过系统选择文件夹对话框添加新验收目录，资料数从 7 增至 11。四份新文件正文全部收录，DOCX 段落文本可见。
3. 点击「整理全部待处理」，队列只处理新增目录的四份资料，旧暂停目录未进入任务。
4. 真实模型成功整理 `04-资料整理.docx`：持久化摘要、`学习计划/资料整理` 分类、关键词和 2 条 tip；两条引用均存在于实际收录正文。
5. `02-英语学习.txt` 遇到一次 `error decoding response body`，App 记录失败原因，保留源文档并显示重试入口，继续处理后续资料。
6. 长文页面观察到第 1/2 段和第 2/2 段进度。随后主动暂停；暂停状态写入磁盘，正在进行的结果未保存为已完成。
7. 正常退出并重开 App，已完成 Word 结果和暂停状态仍在本机索引中。四份测试文件的 SHA-256 均与添加前一致，原路径仍在。
8. 仅启动正式 App 时，TypeWords 服务自动监听 `127.0.0.1:5567`；退出后知识库进程与该监听均结束。未操作词典和练习记录。

## 尚未完成的界面验收

Windows 界面控制工具多次报 `call get_window_state before using this window`，刷新、重新选择窗口和重置会话后仍出现 `unknown screenshotId screenshot-0`。因此停止继续发送界面输入，避免误操作。

以下项目有对应自动化覆盖，但本轮没有完成整套正式安装版界面操作：手动多分类编辑与筛选、tip 定位高亮、原文编辑及撤销、模型失败后的点击重试、暂停后的点击继续和长文最终生成结果。不能将自动化或中途进度视为这些项目的完整实测成功。

合成验收目录已接入并保留，AI 自动整理关闭、任务暂停，可继续人工检查。使用步骤及逐项预期见 [文件知识库使用与验收](DOCUMENT_LIBRARY.md)。

PDF、图片、XLSX、旧 DOC 等本轮仍只收录文件名；不会宣称已经读取这些格式的正文。自动扫描和 AI 队列只在 App 运行时工作。
