# 标签与文章资料卡规范

## 目标

知识库使用两套互补系统，不让文件夹、标签和文章属性互相重复：

1. **标签体系**：回答“这篇资料涉及哪些知识”。用于跨文件检索、筛选、词云和知识图谱。
2. **文章资料卡**：回答“这是什么资料、从哪里来、何时录入”。用于识别单篇文档和属性数据库。

文件夹继续表达稳定的存储层级，标签不代替文件夹，资料卡也不代替正文。

## 标签体系

- 唯一存储字段为 `tags`。
- 标签等同于关键词，支持手动编辑和 Agent 拆解。
- 标签可以按主题概念、方法、对象和证据四种语义类型观察。
- 点击左侧标签可以筛选文件树。
- 图谱使用同一组标签构建知识分类关系，不维护第二份隐藏标签。

## 文章资料卡

| 字段 | 含义 |
| --- | --- |
| `summary` | 一句话说明资料解决的问题或提供的价值 |
| `document_type` | 论文、文章、书籍、摘录、笔记、日记等 |
| `category` | 领域、主题或项目分类 |
| `source` | URL、书名、机构或采集渠道 |
| `author` | 作者、机构或整理者 |
| `created` | 录入知识库的日期 |
| `published` | 原资料的发布日期 |

App 可以读取 `description`、`abstract`、`type`、`domain`、`url`、`authors` 等常见别名，但编辑后以表中的规范字段为准。

## Markdown 示例

```markdown
---
summary: "说明标签体系如何帮助知识库完成跨文档分类。"
tags: ["知识管理", "标签体系", "信息架构"]
document_type: "文章"
category: "知识管理 / 信息架构"
source: "https://example.com/article"
author: "作者或机构"
created: "2026-07-24"
published: "2026-06-18"
---
# 标签体系设计
```

新建文档会自动生成资料卡结构、录入日期和默认文档类型。已有文档不会被批量改写；用户编辑并保存资料卡时才会补齐规范字段。
